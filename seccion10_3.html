El Corazón: Event Log

DLT no es una caja negra. Cada acción, error, métrica de calidad o actualización de esquema se guarda en una tabla Delta oculta llamada Event Log.

Estructura del Evento JSON

system.events 
{
  "id": "001-abc-event",
  "sequence": {
    "control_plane_id": "uuid",
    "seq_no": 123
  },
  "timestamp": "2023-10-25T14:30:00.000Z",
  "event_type": "flow_progress",  // <--- CLAVE
  "details": {
    "flow_progress": {
      "metrics": {
        "num_output_rows": 5000,
        "num_invalid_rows": 12
      },
      "data_quality": {
        "dropped_records": 12,
        "expectations": [
          {"name": "valid_id", "dataset": "silver_users", "passed_records": 4988, "failed_records": 12}
        ]
      }
    }
  }
}

Consultando el Log

Como el log es una tabla Delta, podemos usar SQL o PySpark para crear dashboards de monitoreo personalizados.

monitor_quality.sql SQL 
SELECT
  timestamp,
  details:flow_progress.metrics.num_output_rows as rows,
  details:flow_progress.data_quality.dropped_records as drops
FROM event_log_raw
WHERE event_type = 'flow_progress'
ORDER BY timestamp DESC;
parse_expectations.py PYTHON 
# Explotar el array de expectativas para ver fallos por regla
df_events.filter("event_type = 'flow_progress'") \
  .select(explode("details.flow_progress.data_quality.expectations").alias("rule")) \
  .select(
      "rule.name", 
      "rule.dataset", 
      "rule.failed_records"
  ).display()

Ciclo de Vida Operacional

DLT ofrece dos modos de ejecución distintos que afectan el costo y el comportamiento ante fallos.

Modo Desarrollo

  • Reutilización de Cluster: Mantiene el cluster encendido para iteraciones rápidas de código.
  • Sin Reintentos: Si falla, falla inmediatamente para que puedas depurar.

Modo Producción

  • Reintentos Automáticos: Si un error transitorio ocurre, reintenta automáticamente antes de alertar.
  • Nuevo Cluster por Run: (En modo Triggered) Asegura un ambiente limpio para cada ejecución.
