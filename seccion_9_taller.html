Construyendo la Imagen

Vamos a escribir nuestro propio Dockerfile. Spark está escrito en Scala (que corre en la JVM), por lo que nuestra imagen de Python necesita Java obligatoriamente.

Dockerfile Define el entorno 
# 1. Base ligera de Python
FROM python:3.10-slim

# 2. Instalar Java (Requisito OBLIGATORIO para Spark)
# También instalamos 'procps' para ver procesos y 'curl'
RUN apt-get update && \
    apt-get install -y default-jdk procps curl && \
    apt-get clean

# 3. Variables de Entorno Clave
ENV JAVA_HOME=/usr/lib/jvm/default-java
ENV SPARK_VERSION=3.5.0

# 4. Instalar Spark y Delta vía Pip
# Esto descarga los binarios de Spark y los wrappers de Python
RUN pip install --no-cache-dir \
    pyspark==${SPARK_VERSION} \
    delta-spark==3.0.0 \
    pandas \
    jupyterlab

# 5. Directorio de trabajo
WORKDIR /app

# 6. Exponer puertos (Jupyter y Spark UI)
EXPOSE 8888 4040

# 7. Comando de inicio: Jupyter Lab
CMD ["jupyter", "lab", "--ip=0.0.0.0", "--allow-root", "--no-browser", "--NotebookApp.token=''"]

¿Qué es un Data Lakehouse?

Combinamos lo mejor de dos mundos: la flexibilidad de un Data Lake (archivos baratos) y la confiabilidad de un Data Warehouse (transacciones ACID).

graph LR Raw[Datos Crudos] -->|Ingesta| Bronze[(Capa Bronce\nRaw Delta)] Bronze -->|Limpieza| Silver[(Capa Plata\nClean Delta)] Silver -->|Agregación| Gold[(Capa Oro\nBusiness Delta)] style Bronze fill:#cd7f32,stroke:#fff,color:#000 style Silver fill:#c0c0c0,stroke:#fff,color:#000 style Gold fill:#ffd700,stroke:#fff,color:#000
Bronce: Copia exacta del origen (CSV, JSON). "La verdad cruda".
Plata: Datos limpios, tipados y deduplicados. Listo para Data Science.
Oro: Agregaciones de negocio (KPIs). Listo para BI/Tableros.

¿Por qué Delta Lake?

  • Transacciones ACID: O se escriben todos los datos o ninguno. Adiós a archivos corruptos a medias.
  • Schema Enforcement: Si intentas guardar texto en una columna numérica, Delta bloquea la operación.
  • Time Travel: Puedes consultar cómo estaban los datos ayer con VERSION AS OF.

Fase 1: Ingesta (Capa Bronce)

Vamos a leer el archivo CSV de SECOP. Spark distribuirá la lectura entre los workers.

01_setup_session.py 
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, to_date, sum, desc

# 1. Inicializar Spark con soporte para Delta
spark = SparkSession.builder \
    .appName("Lakehouse_SECOP") \
    .config("spark.jars.packages", "io.delta:delta-spark_2.12:3.0.0") \
    .config("spark.sql.extensions", "io.delta.sql.DeltaSparkSessionExtension") \
    .config("spark.sql.catalog.spark_catalog", "org.apache.spark.sql.delta.catalog.DeltaCatalog") \
    .getOrCreate()

print("Cluster activo. Workers listos.")
02_read_csv.py 
# 2. Leer datos crudos (Lazy Evaluation)
# header=True: Usa la primera fila como nombres de columna
# inferSchema=True: Spark intenta adivinar tipos (lento pero útil para prototipos)
df_raw = spark.read \
    .format("csv") \
    .option("header", "true") \
    .option("delimiter", ",") \
    .option("inferSchema", "true") \
    .load("data/SECOP_II_Contratos_Electronicos.csv")

# Persistir en formato Delta (Capa Bronce)
# Esto convierte el CSV lento en formato Parquet optimizado + Transaction Log
df_raw.write.format("delta").mode("overwrite").save("lakehouse/bronze/secop")

print(f"Total registros: {df_raw.count()}")
df_raw.printSchema()

Fase 2: Limpieza (Capa Plata)

Los datos crudos son un caos. Nombres de columnas con espacios, fechas como texto, valores nulos. Vamos a arreglarlo.

Diagrama de Transformación

graph TD A[Bronce: df_raw] --> B{Filtro de Calidad} B -->|Precio > 0| C[Renombrar Columnas] C -->|Standard| D[Casteo de Tipos] D --> E[Plata: df_silver] style A fill:#cd7f32,stroke:#fff style E fill:#c0c0c0,stroke:#fff,color:#000
03_clean_silver.py 
# Leer desde Bronce (ahora es rápido porque es Delta)
df_bronze = spark.read.format("delta").load("lakehouse/bronze/secop")

# Transformaciones
df_silver = df_bronze \
    .withColumnRenamed("Precio Base", "precio_base") \
    .withColumnRenamed("Departamento", "departamento") \
    .withColumnRenamed("Fecha de Firma", "fecha_firma_str") \
    .withColumn("fecha_firma", to_date(col("fecha_firma_str"), "MM/dd/yyyy")) \
    .filter(col("precio_base") > 0) \
    .select("entidad", "departamento", "precio_base", "fecha_firma")

# Guardar en Plata
df_silver.write.format("delta").mode("overwrite").save("lakehouse/silver/secop")

print("Datos limpios guardados en capa Plata.")
df_silver.show(5)

Fase 3: Analítica (Capa Oro)

Finalmente, respondemos preguntas de negocio. Agrupamos los datos limpios para dashboards.

04_gold_analytics.py 
# Pregunta: ¿Cuáles son los departamentos con mayor contratación?
df_gold = df_silver \
    .groupBy("departamento") \
    .agg(sum("precio_base").alias("total_contratado")) \
    .orderBy(desc("total_contratado")) \
    .limit(10)

# Guardar resultado final
df_gold.write.format("delta").mode("overwrite").save("lakehouse/gold/top_deptos")

# Convertir a Pandas para graficar (Solo porque son 10 filas)
pdf = df_gold.toPandas()
print(pdf)
